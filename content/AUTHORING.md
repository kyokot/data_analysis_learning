# コンテンツ執筆ガイド

`content/units/<単元id>.json` に、単元ごとの **要点（lesson）** と **問題（questions）** を書くための規約です。
人が書く場合もAIが書く場合も同じ規約に従います。

## 0. 大原則

1. **すべてオリジナル**。公式問題・市販の問題集・他サイトの問題や解説文を写さない（数値だけ変えた焼き直しも不可）。
   題材（場面・データ）は自分で作る。データは「架空」でよいが、現実にありそうな値にする。
2. **正確さが最優先**。数値の答えは必ずプログラム（pythonなど）で計算して確かめる。暗算・目分量で確定させない。
3. **正答はちょうど1つ**。問題文の条件だけで答えが一意に決まること。解釈が割れる表現を残さない。
4. **初学者が読める日本語**。専門用語は初出で言い換える。解説は「なぜそうなるか」を1行ずつ追える形にする。
5. **範囲を守る**。統計検定4級・3級の出題範囲の外（t分布、不偏分散、カイ二乗検定、重回帰など）は扱わない。
   名前に触れる必要があるときは「2級以上の範囲」と明記して深入りしない。

## 1. 記法の決まりごと（当サイトでの統一）

| 項目 | 決まり |
|---|---|
| 分散・標準偏差 | **nで割る**（高校数学I・3級の定義）。$s^2=\frac{1}{n}\sum (x_i-\bar{x})^2$。n−1で割る不偏分散は使わない |
| 四分位数 | **高校数学Iの方式**。データを小さい順に並べ、中央値で下半分・上半分に分ける（データ数が奇数のとき中央値自身はどちらにも入れない）。下半分の中央値が第1四分位数、上半分の中央値が第3四分位数 |
| 外れ値 | 「第1四分位数− 1.5 × 四分位範囲」より小さい値、または「第3四分位数+ 1.5 × 四分位範囲」より大きい値。使うときは問題文に基準を書く |
| 階級 | 「a以上b未満」。階級値は (a+b)/2 |
| 相関係数 | $r=\dfrac{s_{xy}}{s_x s_y}$（共分散もnで割る） |
| 正規分布 | $N(\mu,\sigma^2)$ と書く（第2引数は分散）。標準正規分布の確率は**問題文に必要な値を与える**（例:「$P(Z\geqq 1.96)=0.025$ としてよい」）。受験者が数表を引く前提にしない |
| 信頼区間 | 95%は1.96を使う。母標準偏差が既知、または標本が十分大きい場合のみ扱う（t分布は範囲外） |
| 表記 | 和文と数字・英字の間に空白を入れない（「20%」「5人」「第3四分位数」）。単位は日本語で（点・人・円・cm） |
| 丸め | 丸めが必要な問題は「小数第2位を四捨五入して」のように問題文に明記する。選択肢どうしは丸め方の違いで逆転しない程度に離す |
| 不等号 | 日本の教科書式の $\geqq$ `\geqq`、$\leqq$ `\leqq` を使う |
| 確率 | 分数または小数。分数は既約にする |

## 2. テキストの書き方（RichText）

問題文・選択肢・解説・要点はすべて次の簡易マークアップで書きます。

- `$...$` … 文中の数式（KaTeX）。`$$...$$` … 独立した行の数式
- `**...**` … 強調（多用しない）
- 改行 `\n` … 段落の区切り
- 数式の中の日本語は `\text{}` に入れる（例: `$\text{変動係数}=\dfrac{s}{\bar{x}}$`）
- `$` を通貨記号として使わない（「円」と書く）。HTML・Markdownの表や箇条書き記号は使えない（表は図表の `table` を使う）
- JSONの中ではバックスラッシュを二重にする（`"$\\bar{x}$"`）
- よく使うTeX: `\bar{x}` `\sigma` `\mu` `\sqrt{n}` `\dfrac{a}{b}` `\times` `\div` `\pm` `\leqq` `\geqq` `{}_n\mathrm{C}_r` `\sum_{i=1}^{n}` `x_i` `\%`
- **数式の中でパーセントを書くときは `\%`**。日本語の文中では数式にせず「20%」と書く方が読みやすい

## 3. ファイルの形

```jsonc
{
  "unitId": "central",            // ファイル名と同じ
  "lesson": { ... },              // 要点（当サイトのオリジナル解説）
  "questions": [ ... ]            // 問題
}
```

### 3.1 lesson（要点）

外部教材を読む前後に3分で見返せる「まとめカード」です。教科書の代わりではありません。短く、正確に。

```jsonc
{
  "intro": "1〜2文。この単元で何ができるようになり、なぜ必要か。",
  "points": [                       // 3〜6個。1つ150字程度まで
    { "title": "中央値は「真ん中の順位」の値", "body": "小さい順に並べて…" }
  ],
  "formulas": [                     // 任意。0〜6個。texには $ を付けない
    { "name": "平均値", "tex": "\\bar{x}=\\dfrac{x_1+x_2+\\cdots+x_n}{n}", "note": "任意の補足" }
  ],
  "example": {                      // 例題1つ。本試験の標準的な問い方で
    "problem": "…",
    "figure": { ... },              // 任意
    "steps": ["手順1 …", "手順2 …"],   // 2〜7個。1手順1行
    "answer": "中央値は6.5点"
  },
  "pitfalls": ["よくある間違いと、その直し方", "…"],     // 2〜5個
  "examTips": ["試験での問われ方・時間の使い方", "…"]    // 1〜4個
}
```

### 3.2 questions（問題）

```jsonc
{
  "id": "central-q01",        // <単元id>-q<2桁連番>。並び順どおり
  "grade": 4,                 // この問題が出題範囲に入る最も下の級（4または3）
  "difficulty": 2,            // 1 = 基礎の確認 / 2 = 本試験の標準 / 3 = 本試験のやや難
  "pool": "practice",         // practice = 確認テスト・復習用 / exam = 模試専用
  "skill": "中央値（データ数が偶数）",   // この問題で問う技能。40字以内の名詞句
  "stem": "次のデータは…。中央値として正しいものを一つ選べ。",
  "figure": { ... },          // 任意
  "choices": ["5", "6", "6.5", "7"],   // 4個または5個
  "answer": 2,                // 正答の添字（0始まり）
  "explanation": "小さい順に並べると…",   // 正答の考え方。計算は途中式を見せる
  "choiceNotes": [            // 選択肢ごとの一言。choicesと同じ数・同じ順
    "並べ替えずに、与えられた順のまま真ん中の2つを平均した値。",
    "真ん中の2つのうち小さい方だけを答えた値。",
    "正しい。小さい順に並べて4番目と5番目の平均をとる。",
    "真ん中の2つのうち大きい方だけを答えた値。"
  ]
}
```

#### 単元ごとの問題数と配分

| 単元の種類 | practice | exam | 合計 |
|---|---|---|---|
| 4級の単元（ステージs1） | 8問 | 5問 | 13問 |
| 3級の単元（ステージs2〜s5） | 8問 | 4問 | 12問 |
| 数学の補習（ステージs0） | 6問 | 0問 | 6問 |

- **practice 8問**: difficulty 1を2問、2を5問、3を1問。単元の `goals`（curriculum.json）を**すべて**カバーする。
  確認テスト（5問）と、翌日以降の定着チェック（別の3問）に分けて出題されるので、8問のどの5問・どの3問を取ってもgoalsが偏らないようにする。
- **数学の補習6問**: difficulty 1を3問、2を3問。統計の単元で実際に使う計算だけに絞る（統計の文脈で出す）。
- **exam**: difficulty 2を中心に3を1問。goalsを広くカバーし、practiceと**題材も数値も問い方も変える**（数値替えは不可）。
  模試は「初見の問題で実力を測る」ためのものなので、practiceを覚えていても解けない独立した問題にする。
- `grade`: 4級の単元では原則4。その単元の中で3級でしか問われない深さの問題だけ3（examは必ず4）。3級の単元ではすべて3。
- 正答の位置（`answer`）は単元全体で偏らせない（同じ位置が4割を超えると検証エラー）。

#### 良い問題の条件

- **1問1技能**。`skill` に書いた技能だけで解ける。読解の難しさで差をつけない。
- **本試験の形式**: 4〜5択の単一選択。「最も適切なものを一つ選べ」「正しいものを一つ選べ」。
  「適切でないものを選べ」は1単元2問まで（使うときは **適切でない** と強調する）。
  「上記すべて」「どれでもない」は使わない。複数の記述の正誤の組合せを問う形式（Iのみ正しい／IとIIのみ正しい…）は使ってよい。
- **誤答はすべて「ありがちな間違い」から作る**（計算の取り違え、定義の混同、単位や基準の取り違え）。でたらめな数値は置かない。
- **数値の選択肢は小さい順**に並べる。桁・単位・丸めをそろえる。
- **計算は電卓1つで2分以内**。本試験は電卓持込可だが、1問あたり平均2分しかない。
- 図表を読ませる問題を各単元2問以上入れる（データや図表になじむ単元の場合）。本試験は図表の読み取りが多い。
- 問題文に選択肢番号（①②…）を書かない（番号は画面側で付ける）。図の `panels` を使うときは、パネルの `label` を「A」「B」…にして、選択肢で「A」「B」と参照する。
- 人名は「Aさん」など記号にする。実在の企業・商品・個人は出さない。

#### 解説の書き方

- `explanation`: 最初の文で結論（何が答えか）を言い、次に理由・途中式を示す。計算問題は式 → 数値代入 → 結果の順に。丸める前の値も示す。
- `choiceNotes`: 選択肢1つにつき1文。誤答には「**どう取り違えるとこの答えになるか**」を具体的に書く
  （例:「nではなくn−1で割った値」「行比率ではなく列比率を読んだ値」）。「誤り。」だけの一言は不可。
  学習者は自分が選んだ誤答の一言を見て、間違いの原因を知る。正答の欄は「正しい。」＋決め手を一言。

## 4. 図表（figure）

図は数値データから画面側で描きます。**画像は使えません**。読み取り問題では、読ませたい値が目盛り線にちょうど乗るようにしてください
（例: 箱ひげ図の五数要約は目盛りの刻みの倍数にする）。

```jsonc
// 表（クロス集計表・度数分布表・データ一覧）。セルは文字列か数値。$数式$ も使える
{ "type": "table", "title": "通学時間の度数分布表", "columns": ["階級（分）", "度数（人）"],
  "rows": [["0以上10未満", 4], ["10以上20未満", 9]], "headerColumn": true, "note": "任意の注記" }

// 棒グラフ（系列が複数なら集合棒。stacked: true で積み上げ棒）
{ "type": "bar", "title": "…", "xLabel": "曜日", "yLabel": "来店者数（人）",
  "categories": ["月", "火", "水"], "series": [{ "name": "午前", "values": [30, 45, 40] }], "showValues": true }

// 帯グラフ（構成比 %。各行の合計は 100）
{ "type": "band", "title": "…", "rows": ["2015年", "2020年"],
  "segments": [{ "name": "徒歩", "values": [40, 30] }, { "name": "自転車", "values": [35, 45] }, { "name": "バス", "values": [25, 25] }], "showValues": true }

// 円グラフ（showPercent: true で割合を表示）
{ "type": "pie", "title": "…", "slices": [{ "label": "A", "value": 45 }, { "label": "B", "value": 30 }, { "label": "C", "value": 25 }], "showPercent": true }

// 折れ線グラフ（時系列）。yMin / yMax で縦軸の範囲を指定できる
{ "type": "line", "title": "…", "xLabel": "年", "yLabel": "売上（万円）",
  "x": ["2019", "2020", "2021", "2022"], "series": [{ "name": "店舗A", "values": [120, 100, 130, 150] }], "showValues": false }

// ヒストグラム（等間隔の階級。edges は counts より 1 つ長い）。relative: true なら相対度数
{ "type": "histogram", "title": "…", "xLabel": "得点（点）", "yLabel": "人数（人）",
  "edges": [0, 20, 40, 60, 80, 100], "counts": [2, 5, 12, 8, 3], "showCounts": true }

// 箱ひげ図（横向き。複数並べて比較できる）。outliers はひげの外に点で描く
{ "type": "boxplot", "title": "…", "axisLabel": "得点（点）", "axisMin": 0, "axisMax": 100,
  "boxes": [{ "label": "1組", "min": 20, "q1": 40, "median": 55, "q3": 70, "max": 95 }] }

// 散布図（line で回帰直線 y = intercept + slope·x を重ねられる）
{ "type": "scatter", "title": "…", "xLabel": "気温（℃）", "yLabel": "売上（個）",
  "points": [[20, 35], [22, 41], [25, 50]], "xMin": 15, "xMax": 35, "yMin": 0, "yMax": 100 }

// ドットプロット（整数値）
{ "type": "dotplot", "title": "…", "axisLabel": "本数（本）", "values": [1, 2, 2, 3, 3, 3, 5] }

// 幹葉図
{ "type": "stemleaf", "title": "…", "stemLabel": "十の位", "leafLabel": "一の位",
  "rows": [{ "stem": "1", "leaves": ["2", "5"] }, { "stem": "2", "leaves": ["0", "3", "3", "8"] }] }

// 正規分布（shade で区間を塗る。from 省略 = 左端から、to 省略 = 右端まで）
{ "type": "normal", "title": "…", "xLabel": "身長（cm）", "mean": 170, "sd": 6, "shade": [{ "from": 176 }], "marks": [158, 164, 170, 176, 182] }

// 複数の図を並べる（「A〜D のうち…」形式）。2〜6 枚。入れ子は不可
{ "type": "panels", "title": "…", "panels": [{ "label": "A", "figure": { "type": "scatter", "points": [[1,2],[2,3],[3,5]] } }, { "label": "B", "figure": { ... } }] }
```

- 散布図で相関の強さを読ませるときは、点を15〜30個置き、意図した相関係数になっているかを計算で確かめる。
- 画面はスマートフォン幅（約360px）でも読めること。棒・折れ線の項目は8個程度まで、表は6列程度までにする。
- 色だけで区別させない（系列名は凡例に出る）。問題文で「青い棒」などと色を指さない。

## 5. 仕上げの検証（必須）

1. **機械検証**: `npm run validate:content -- --unit <単元id>` がエラー0件になること。
2. **計算の再確認**: 数値が絡むすべての問題について、pythonなどで正答を再計算し、誤答が本当に誤りであることも確かめる。
3. **独立した解き直し**: 書いた本人とは別の人（または別のAI）が、正答を見ずに全問を解き、答えが一致することを確かめる。
   一致しない問題は、問題文があいまいか、正答が誤っている。直すか、捨てる。
4. **範囲の確認**: 公式の出題範囲表に無い知識を前提にしていないこと。

内容に誤りを見つけたら、公式テキスト（日本統計学会 編）を基準に直してください。

## 6. 類題ジェネレーター（計算問題）

計算で答えが一意に決まる技能は、固定の問題に加えて `src/generators/units/<単元id>.ts` に「類題ジェネレーター」を書けます。
数値を変えた問題を何問でも作り、間違えた問題の出し直し・補強ドリル・定着後のおさらいに使います（模試には使いません）。

- 問題文・選択肢・解説・選択肢メモの書き方は、この文書の決まり（記法・丸め・定義の統一）に従う。
- 正答は必ずコードで計算する。誤答は「典型的な取り違え」をコードで計算し、選択肢メモにその取り違えを書く。
- 丸めが必要な問題は、丸め方の違いで正誤が入れ替わらない数値だけを使う（ぎりぎりの数値は `Reject` で作り直す）。
- 標準正規分布の値など、解くのに必要な値は問題文に与える。
- `replaces` には、ジェネレーターと同じ計算・同じ問い方の practice 問題だけを書く。
- 書いたら `npx vitest run tests/generators.test.ts` を通し、`GEN_SAMPLE=<単元id> npx vitest run tests/gen-sample.test.ts --reporter=verbose` の見本を、書いた本人とは別の人が解いて確かめる。
